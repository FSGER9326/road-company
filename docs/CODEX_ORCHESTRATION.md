# Codex GitHub Orchestration

This document adds the event-driven GitHub layer used to connect ChatGPT web, Codex Web, Codex GitHub Actions, and optional local workers with minimal copy-paste.

## Roles

| Role | Responsibility |
|---|---|
| ChatGPT web | Planner, issue/spec author, reviewer, art director, asset generator. |
| Codex Web / Codex Action | Cloud implementer for repository code, tests, and docs. |
| Local worker | Optional WSL/Windows worker for Godot GUI, Blender, Android, OpenClaw, MCP, or local authenticated tools. |
| GitHub | Shared state, task queue, audit trail, pull requests, and generated asset handoff. |

## Labels

Use these labels consistently:

- `codex:implement` — issue is ready for Codex implementation.
- `codex:review` — PR should receive automated Codex review.
- `codex:autofix` — CI or review failures may be repaired by Codex.
- `codex:generated` — PR or branch was generated by Codex automation.
- `needs:asset` — task requires generated or imported assets.
- `needs:imagen` — ChatGPT/image generation should create art assets first.
- `needs:local-worker` — task requires tools not available to Codex Web/GitHub Actions.
- `agent:blocked` — automation could not proceed without human input.

## Normal implementation flow

1. Create a GitHub issue using `docs/TASK_TEMPLATE.md`.
2. Add `codex:implement` when the issue is ready.
3. GitHub Actions runs Codex.
4. Codex commits to an automation branch and opens a PR.
5. The PR review workflow runs Codex review.
6. ChatGPT or the repo owner reviews the PR and comments follow-up instructions if needed.
7. Codex patches the PR or a human merges it.

## Asset handoff flow

1. ChatGPT generates or prepares assets.
2. Commit assets under `assets/generated/`.
3. Commit a matching manifest under `assets/manifests/`.
4. Create or update an issue describing how the assets should be used.
5. Add `codex:implement` to let Codex integrate the assets.

## Local worker flow

Use `needs:local-worker` for tasks that require tools not available in Codex Web or GitHub Actions:

- Godot GUI validation on Windows.
- Android APK builds.
- Blender asset generation or rendering.
- OpenClaw gateway orchestration.
- Local MCP tools.
- Local authenticated browser sessions.

A local watcher can poll GitHub issues with `needs:local-worker`, run `codex exec` locally, push a branch, and open a PR.

## Human approval policy

Automation should create PRs and comments. It should not merge directly unless the repository owner explicitly enables that later.
